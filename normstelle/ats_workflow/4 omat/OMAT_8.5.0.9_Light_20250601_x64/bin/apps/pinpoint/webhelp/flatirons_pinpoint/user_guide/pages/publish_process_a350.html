Knowledge Center S Publish/Release Process

General Process

Not applicable for Pinpoint Standalone Light.

When a builder connected to Knowledge Center S, for instance the A350 Builder, is selected in the Publish Publication panel in Data Manager, the user will be able to select a Knowledge Center CSDB to publish from and the publication type to publish. The selected publication is then fetched from Knowledge Center S directly, the data is converted from XML to Pinpoint Neutral, and it becomes available as a draft in Pinpoint Viewer. How long this process takes depends on the size of the publication.

Users with the appropriate privileges have access to review the publication revision. They can either choose to release the revision to a set of user groups (Pinpoint viewers), or they can rollback, that is, reject it and remove the revision from Pinpoint and Data Manager. Another option is to reload the revision, which removes the revision and imports it again from Data Manager.

Note: The publication release process described here can be overridden by defining a list of publication types that shall be auto-released in Pinpoint. Be aware that if the publication is auto-released you must remember to manually assign view privileges for the appropriate users in Access Control. For more information about the auto-release configuration, refer to the document Define Publications to be Auto Released in the Flatirons Pinpoint Configuration Guide.


Knowledge Center S Publish/Release Process

Note: The process described here applies to documentation published using the A350 Builder and XWB KCt Builder. It does not apply to documentation published with the CMM Builder (autorelease). CRDM is another exception. The CRDM must be published before other publications as the data it contains is used by the other publications. There is no release or rollback available for CRDM as it is automatically released in Pinpoint. It will not appear in Pinpoint's table of content.

Related Privileges

These privileges in Access Control module panel are related to the publish process:
  • Data Manager > application > Can download draft: This resource is used by the Pinpoint Application User to download publications from Data Manager (using e.g. the A350 builder) to Pinpoint. You will need "Read" permissions to that resource to be able to download draft revisions.
  • Pinpoint > configuration > Can release or rollback draft revisions: The user group that can release, rollback, and reload publication revisions in Pinpoint needs to have Read permission to this resource to be able to see and use the rollback/release/reload buttons. Users that do not have this privilege will not be able to see draft revisions in Pinpoint, they will only see the latest released revisions.
  • Pinpoint > data > [publication name] > [revision number]: The user group that can release, rollback, and reload publication revisions in Pinpoint needs to have Read/Write/Delete permission to the publication revision in order to perform release/rollback/reload.

Publishing from Data Manager

The publishing from Knowledge Center S to Pinpoint Viewer is initiated in Data Manager by creating a repository library, a publication plus selecting the appropriate CSDB and publication type. For detailed instructions about the publishing, refer to the section "Create/Publish Publication" in the Flatirons Data Manager User Guide.

Note: Remember that the CRDM must be imported before any other publication types. The CRDM publishing is complete when you see a checkmark in the Released field of the Revisions section for the publication in Data Manager.

If the publishing is successful, the publication will become available as a draft revision for the Pinpoint users that have the appropriate privileges.

As long as the latest publication revision is in draft status, you will not be allowed to add a new revision from Data Manager. (The Add New Revision button will be disabled.) When the publication is released in Pinpoint Viewer, you will see a checkmark in the Released field.

If the publishing fails, Log and Resynch buttons are available under the Publication Operations button in the Pinpoint header bar. These allow the user to investigate the problem and retry the operation. In addition, Data Manager will attempt to send an e-mail about the publish failure to a set of pre-defined users.
Note: There is a description of how to configure the e-mail notification in the Pinpoint Configuration guide (PDF document delivered together with the application). If not configured properly or if the e-mail server is not running/reachable, the following warning message will be thrown when Data Manager is trying to send a failure notification: E-mail server is not available or not configured properly

The e-mail notification contains information that identifies the publication, summarizes the problem and provides troubleshooting guidance.

Release, Rollback, and Reload in Pinpoint Viewer

When releasing a publication in Data Manager, the publication can be released as a draft or released automatically by checking the Auto Release checkbox. If the publication was auto released and the release was successful, the Publication Operations icon is not visible in the Pinpoint Viewer.

Only users with the appropriate permissions can view the publication and do release, rollback, or reload on the publication revision draft using these functions under the Publication Operations icon in the header bar:
  • – When pressed, a new dialog with user groups appears. The groups chosen in this dialog will get access to the released version. Refer to Release a Publication Revision for more information.
  • – When pressed, the publication revision is removed from the Pinpoint Viewer and the Data Manager. The publication revision resource is also removed from the privilege tree in Access Control module. Refer to Rollback a Publication Revision for more information.
  • – When pressed, the selected publication revision is deleted, and the revision is imported again from Data Manager. Refer to Reload a Publication Revision for more information.
    Note: You may experience up to a 60-second delay after the reload is complete before the import of the revision begins.
