Migrate Attachments

Not applicable for Pinpoint Standalone Light.

Note: This procedure is intended only for users who handle publishes, releases, and/or rollbacks. Migrating attachments requires having all permissions enabled for Can Upload Supplement.
For libraries that are managed directly with Pinpoint (instead of indirectly with Knowledge Center a), all attachments are automatically migrated whenever there is a publish/release/rollback. Whatever attachments that were available in the previous official revision are automatically made available to the current draft revision for these libraries. This procedure is not needed for this situation.
Note: If somebody later adds an attachment to an earlier revision than the latest available, attachments are not automatically migrated into the more recent revisions.

However, Pinpoint cannot automatically detect when there has been a new publish/release/rollback of a publication in Knowledge Center a, so it cannot automatically migrate Pinpoint Viewer attachments for Knowledge Center a libraries. Only Knowledge Center a attachments that were part of the data package are automatically made available. After doing a publish/release/rollback of a Knowledge Center a publication, it is necessary to manually select the menu option from the Publication Operations menu. This menu option is not available for other libraries that are managed directly with Pinpoint because all attachments are safely migrated automatically for those other libraries.

For Knowledge Center a/Pinpoint a documents, the Publication Operations menu option migrates the Pinpoint Viewer attachments from the current official revision to the current draft revision. If this menu option is not used before doing a release of a Knowledge Center a/Pinpoint a publication. the attachments that were available for the previous revision will not be available for the latest released revision.

After doing a publish/release/rollback of a Knowledge Center a publication, do these steps to migrate Pinpoint Viewer attachments from the current official revision to the current draft revision:

  1. Open a draft revision of a Knowledge Center a/Pinpoint a publication.
  2. From the Publication Operations menu, select the menu option.
    A confirmation pop-up is shown that asks if you want to migrate all attachments from the current revision to the draft revision.
  3. Click the Confirm button.

A green confirmation dialog confirms that the attachments have been successfully migrated from the previous revision to this revision. In other words, any attachments from the current official revision have been migrated to the next revision that you are currently viewing in draft state.

You can view the migrated attachments in the Attachments pane. For documents that have a different revision number compared to the previous publication revision, a conflict icon is shown. Refer to Attachments Pane.
Note: If an attachment was attached to the content that has been deleted in a future revision, then the migrate attachment feature will not migrate the attachment when the new revision has been published. Therefore, no conflict will be generated in the Annotation/Supplement pane UI. However, the attachment will still be viewable in the previous revision if the user has permissions to "Can View All Draft Content" and "Can View All Released Content" privileges in ACM.
