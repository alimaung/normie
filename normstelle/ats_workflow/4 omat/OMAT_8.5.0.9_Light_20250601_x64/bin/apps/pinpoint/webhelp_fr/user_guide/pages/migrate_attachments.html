Migrer les Attachements

Non applicable pour Pinpoint Standalone Light.

Remarque : Cette procédure est destinée uniquement aux utilisateurs qui gèrent les publications, les versions et / ou les annulations. Migration les attachements nécessitent que toutes les autorisations soient activées pour pouvoir télécharger un supplément.

Pour les bibliothèques gérées directement avec Pinpoint (au lieu d’indirectement avec Knowledge Center A), toutes les attachements sont automatiquement migrés chaque fois qu'il y a une publication / publication / restauration. Quelles que soient les attachements disponibles dans la précédente révision officielle sont automatiquement mis à la disposition du projet de révision en cours pour ces bibliothèques. Cette n'est pas nécessaire pour cette situation.

Remarque : Si quelqu'un ajoute ultérieurement une attachement à une révision antérieure à la dernière version disponible, les attachements ne sont pas automatiquement migrées dans les révisions les plus récentes.
Cependant, Pinpoint ne peut pas détecter automatiquement la nouvelle publication / publication / restauration d'une publication dans Knowledge Center A, il ne peut donc pas migrer automatiquement les attachements de la Visionneuse Pinpoint pour Knowledge Center A bibliothèques. Seul Knowledge Center A attachements qui faisaient partie de la paquet de données sont automatiquement disponibles.

Après avoir publié / publié / annulé une publication du Knowledge Center, il est nécessaire de sélectionner manuellement l'option de menu Migrer les attachements dans le menu Opérations de publication. Cette option de menu n'est pas disponible pour d'autres bibliothèques gérées directement avec Pinpoint car toutes les attachements sont migrées automatiquement en toute sécurité pour ces autres bibliothèques.

Pour Knowledge Center A / Pinpoint documents, l'option de menu Opérations de publication migre le Pinpoint attachements de la visionneuse de la révision officielle actuelle au projet de révision actuel. Si cette option de menu n'est pas utilisée avant de faire une version d'un Knowledge Center a / Pinpoint une publication. les attachements qui étaient disponibles pour le la révision précédente ne sera pas disponible pour la dernière révision publiée.

Après avoir publié / publié / annulé une publication du Knowledge Center, procédez comme suit pour migrer les attachements de la Visionneuse Pinpoint de la révision officielle actuelle vers la version provisoire actuelle:
  1. Ouvrez un projet de révision du Knowledge Center A / Pinpoint publication.
  2. Dans le menu Opérations de publication, sélectionnez l'option de menu Migrer les attachements. Une fenêtre contextuelle de confirmation s'affiche vous demandant si vous souhaitez migrer toutes les attachements de la révision actuelle vers la projet de révision.
  3. Cliquez sur le bouton Confirmer.

    Une boîte de dialogue de confirmation verte confirme que les attachements ont bien été migrées à partir de la précédente révision de cette révision. En d'autres termes, toutes les attachements de la révision officielle actuelle ont été migrées vers le prochaine révision que vous consultez actuellement à l'état de brouillon.

    Vous pouvez afficher les attachements migrées dans le volet Attachements. Pour les documents dont la révision est différente par rapport à la révision de publication précédente, une icône de conflit s'affiche. Reportez-vous au Volet des Attachements.
    Remarque : Si une pièce jointe était jointe à un contenu qui a été supprimé dans une révision ultérieure, la fonctionnalité de migration de pièce jointe ne migrera pas la pièce jointe lors de la publication de la nouvelle révision. Par conséquent, aucun conflit ne sera généré dans l'interface utilisateur du volet annotation/Supplément. Cependant, la pièce jointe sera toujours visible dans la révision précédente si l'utilisateur dispose des autorisations "Peut afficher tout le brouillon de contenu" et "Peut afficher tout le contenu publié" dans ACM.
