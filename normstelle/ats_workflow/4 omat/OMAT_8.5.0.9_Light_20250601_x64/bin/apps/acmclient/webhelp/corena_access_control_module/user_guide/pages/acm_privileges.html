Permissions for Access Control Manager

The management of permissions (who can do what) in Access Control Manager itself is also managed in Access Control Manager. Access Control Manager administrators must therefore be added to a user role that has permissions to operate Access Control Manager.

Read, Write, and Delete permissions can be granted for the following nodes below the Access Control Manager privilege tree for both User Roles and Organizations:



Access Control Manager Privilege Tree

Table 1. Access Control Manager Privilege Tree
Node (Top Level > Sub Levels) Description
Configuration

Grant the appropriate permissions to the Configuration page (opened by clicking the Configuration icon on the header bar):

  • Read permission enables the user to view the Configuration page.
Configuration > Authentication Provider

Grant the appropriate permissions to the Authentication Provider page below Configuration:

  • Read permission enables the user to view the Authentication Provider page.
  • Write permission allows the user to switch authentication provider.
Configuration > Encryption

Grant the appropriate permissions to the Encryption page below Configuration:

Read permission enables the user to enter an input string (password) and generate an encrypted password that can be copied to the clipboard.
Configuration > LDAP Configuration

Grant the appropriate permissions to the LDAP Configuration page below Configuration:

Read permission enables the user to view the LDAP Configuration. Write permission allows the user to edit the fields on the page.
Configuration > Permission Types

Grant the appropriate permissions to the Permission Types page below Configuration:

  • Read permission allows the user to view Permission Types.
  • Write permission allows the user to edit existing and create new permission types.
  • Delete permission allows the user to delete existing permission types.
Configuration > SAML Configuration

Grant the appropriate permissions to the SAML Configuration page below Configuration:

  • Read permission enables the user to view the SAML Configuration page.
  • Write permission allows the user to edit the fields on the page.
Organizations

Grant full (Read/Write/Delete) permission to the Organizations page (opened by clicking the Organizations icon on the header bar).

  • Read permission allows the user to view the Organizations page.
  • Write permission allows the user to edit existing organizations and create new.
  • Delete permission allows the user to delete organizations.
Privileges

Grant the appropriate permissions to the Privileges page (opened by clicking the Privileges icon on the header bar):

  • Read permission allows the user to view and navigate in the Privileges page.
  • Write allows the user to edit and assign permissions to user groups.
Important:

At least one user group needs to have both Read and Write permission on the Privileges-resource. If a user tries to remove the last existing user group with these permissions, he will get an informative error-message about this.

It should be noted that users are allowed to remove their own user group's read and write permissions on the Privileges-resource as long as another user group has read/write-permission on this resource. This will result in an lock-out for himself, and the user needs to contact a user of that other user group to get back his permissions.
Privileges > Can share content with other organizations Grant the appropriate permissions for being able to share your organization’s published data with other organizations. This option does not allow you to change access of data from other organizations. Refer to Manage Function Privileges and Data Access Permissions.
User Groups

Grant the appropriate permissions to the User Groups page (opened by clicking the User Groups icon on the header bar):

  • Read permission allows the user to view the User Groups page.
Users

Grant the appropriate permissions to the Users page (opened by clicking the Users icon on the header bar):

  • Read permission allows the user to view the Users page. Refer to Users.
  • Write permission allows the user to change the organization connected to a user. Refer to Change Organization for a User.

Instructions for how to grant permissions are found in Manage Function Privileges and Data Access Permissions
