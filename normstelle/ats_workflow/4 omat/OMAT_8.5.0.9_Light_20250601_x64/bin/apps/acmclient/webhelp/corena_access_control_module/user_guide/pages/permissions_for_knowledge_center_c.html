Permissions for Knowledge Center Manufacturer (KCM)

The control of permissions (who can do what) in Knowledge Center Manufacturer (KCM) is managed in Access Control Manager (). The Access Control Manager administrator grants permissions to the different user roles/organizations that can access functions in KCM.

For a description of how to grant permissions to user roles/organizations, refer to Manage Function Privileges and Data Access Permissions.

Read, Write, and Delete permissions can be granted for the nodes below the KCM privilege tree. However, KCM requires only Read permission to access its functionalities.

CORENA FLOW Privilege

The privileges for CORENA Flow are common across all CSDBs. Permission for CORENA Flow allows access to FLOW Module Administration from the Configuration menu. If this permission is not given, the Configuration menu is disabled in KCM. For example:


Configuration Menu Disabled

When you create a new CSDB, based on the product scope of the CSDB (S1000D or iSpec), the privileges are saved under the CSDB. When the configuration kits are imported, the list of privileges are posted under the specific CSDB. Those privileges are required to access the KCM functions for that CSDB.

Assigning Permissions

An administrator must grant Read permission for a user to be able to access the KCM functions. If a user, as a member of a user role or organization, does not have permission for a function, the user cannot access that function. These permissions control and restrict user access to KCM functions.
Note: Users must have Read permission for Application to allow them access to KCM.

Here are some examples:

  • If a user does not have permission for View CSDB for a specific CSDB, the user cannot see that CSDB in KCM.
  • If a user does not have permission for Delete Delivery under Delivery, the user cannot delete a delivery from KCM Delivery Management.
