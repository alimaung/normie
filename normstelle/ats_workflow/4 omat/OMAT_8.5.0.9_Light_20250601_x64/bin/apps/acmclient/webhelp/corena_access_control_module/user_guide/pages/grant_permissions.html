Manage Function Privileges and Data Access Permissions

To manage function privileges and data access permissions, do these steps:

  1. Click the Privileges icon on the header bar.
    The Privileges page opens:


    Privileges Page Example

  2. From the drop-down menu located at the top of the left-side pane, select the item category for which you want to modify permissions:
    • To modify the data access permissions available to user groups within your organization, select User Groups. For example, this option can be used to set which manuals can be seen in Pinpoint Viewer.
    • To modify the function privileges available to user roles within your organization, select User Roles. For example, this option can be used to set which administration functions are available to which user roles.
    • If you belong to your organization’s "[NCAGE] Organization Administrators" user role or you are a system administrator, there is an Organizations item category option. Select this menu option to do the following:
      • As an organization administrator (or as a user belonging to a role with access to Privileges > Can share content with other organizations), you can share your organization’s imported/published data with other organizations. This option does not allow you to change access of data from other organizations. After giving new data access permissions to an organization with this option, that organization will now be able to setup the data permission differences within their organization by selecting the User Groups item category option.
      • As a system administrator, you can additionally modify the function privileges that are available to each separate organization. After giving new function privileges to an organization with this option, that organization will now be able to setup the function privilege differences within their organization by selecting the User Roles item category option.

    The left pane list switches to the selected item category. If you selected User Roles or User Groups, you can only see user roles or groups that belong to your organization.

    The right pane shows a Privileges tree. The top parents are the products available to your organization. The children available to each product parent depend on which menu option you selected:
    • If you selected User Groups, only data nodes are shown under products that contain manual data. Unless you are a system administrator, you can only see data nodes that were published/imported by your organization, as well as data nodes that were shared by other organizations.
    • If you selected User Roles, only function privilege nodes are shown under each product. You can only see function privileges that were shared with your organization by a system administrator.

    • If you selected Organizations, typically only data nodes are shown under products that contain manual data. In this case, you can only see data nodes that were published/imported by your organization.

      But for system administrators, both data nodes and function privilege nodes are shown together, and all data nodes can be seen regardless of who published the content.

  3. Optional: To reduce the number of items in the list, type a full or partial item name in the left-side pane Search field and click the search icon.
  4. From the left-side pane, do one of these choices:
    • To select a single item, locate and select it.
    • If you selected User Groups or Organizations and you want to select multiple items.,click the Select multiple icon.
      The Selections box appears.


      Selections Box Example

      Select multiple items by clicking them and using the arrow icons to move the selected items to the Selections box:
      • Click the add all arrows icon to add all items for the page to the Selections box.
        Note: You must do this for each page of items.
      • Select an item and click the add arrow icon to add the item to the Selections box.
      • Select an item and click the remove arrow icon to remove the item from the Selections box.
      • Click the remove all arrows icon to remove all items from the Selections box.
  5. Optional: To copy/paste permissions between items:
    • Select the item to copy permissions from and click the Copy icon.
    • Select the item to paste permissions to and click the Paste icon.

      A confirmation message appears.

      Click the OK button to paste the copied permissions. This will overwrite all permissions previously set for the selected item.

  6. Optional: To reduce the number of nodes in the Privileges tree, do any or multiple of these filtering options:
    • Type a full or partial node name in the Privileges pane Search field and click the search icon.
    • From the Show contexts drop-down menu, select a specific product.
    • From the Show drop-down menu, select the permission you want to filter on:
      • Show all – This is the default option.
      • Show Read permissions – For example, this option is useful for showing only data that can be seen by the selected user groups/organizations.
      • Show Write permissions – For example, this option is useful for showing function privileges that could be administrative in nature that are currently available to the selected user roles/organizations. However, many function privileges may have the Write permission set that do not actually involve a write capability.
      • Show Delete permissions – For example, this option can show function privileges with the Delete permission currently activated for the selected user roles/organizations. However, many function privileges may have the Delete permission set that do not actually involve a delete capability.
    The Privileges tree now only shows the nodes that satisfy your filtering criteria.
  7. From the Privileges tree, locate and select the node(s) for which you want to modify permissions.

    You can use Ctrl + left click to make multiple selections. Any permissions you change apply to all of the selected nodes when you click the Save icon.

    The numbers in parentheses next to the permission (Read, Write, and Delete) show the number of category items with that permission for the selected node.
  8. If you selected User Groups or Organizations, click the appropriate tab:
    • To view/assign permissions for the currently selected node(s), click the Current Permissions tab.
    • To define default permissions for future node descendants, click the Default Permissions tab. For example, you can use this option to automatically share future revisions that are created under that node.

      When you create a new node, it looks up the tree and takes the default permissions from the first node that has default permissions. It does not take permissions from every node above it with default permissions.

      Note: When you set permissions in this tab, they are not set for the currently selected node(s). The permissions are used when a new node is created and can be overwritten individually, if necessary.
  9. Optional: To see the items that currently have that permission for the selected node, do these substeps:
    1. Click a number in parentheses to the right of a permission.
      A Group(s) with Privilege dialog opens. For example, if you selected a data node and clicked the number to the right of the Read permission, this dialog can be useful for showing which groups/organizations can see the selected data.


      Group(s) with Privilege Dialog Example

    2. Optional: Scroll through the list and/or click the page buttons to see all of the items that currently have that permission for the selected node.
    3. When you are done, click the Cancel selection icon.
  10. Click the Edit icon.
    The Permissions section can now be edited.
  11. Modify the appropriate permissions checkboxes as needed:
    • Read
    • Write
    • Delete
    Note: For slow networks only, a loading indicator starts when you click a node or when you activate/deactivate permissions. The loading indicator stops when permissions are set, including those for child nodes.


    Grant Permissions Example

  12. Optional: If you are editing the Current Permissions and you want to apply the same set of changed permissions to all visible descendants of the current node, activate the Apply to descendants checkbox

    The tool tip for the checkbox gives information about how this feature works.

    Note: You must activate this checkbox before saving your permission changes in order for descendants to inherit the changes.

    When you activate this option, it only applies to children nodes that are visible, ignoring the children that are not available to your organization. It also only applies to the current changes. You must activate this checkbox each time you make changes in order to have them apply to descendants.

  13. The user will see the updated Prefix values in the structure based on the privileges provided, indicating the current R/W/D privileges of the node for the selected Group.


    R/W/D Privileges Example

  14. Click the Save icon.

The changes you made are saved to the selected items. Changed permissions appear in italic text.

After completing this procedure, you can do the following:
  • If you have completed setting up the User Groups item category, you can now confirm with a test user in each group that the visibility of data was modified successfully in the applicable applications for your organization.
  • If you have completed setting up the User Roles item category, you can now confirm with a test user in each role that the function privileges were modified successfully in the applicable applications for your organization.
  • If you have completed setting up the Organizations item category, organization administrators can now follow this procedure with the User Groups and User Roles item categories to setup access permission differences and/or function privileges within their separate organizations.
