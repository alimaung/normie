Authentication

Authentication is performed using an alphanumeric API key that must be included in the request header.
You can find your existing API key or generate a new one by going to your Businessmap account and in the top-right corner clicking My Account -> API:

Once you have opened the API section, you can click Show API key to view it, or Copy to clipboard to easily copy the key for use in your requests.

Important

Please note that if you generate a new API key, your current one will be permanently deleted, which may affect any existing integrations that rely on it.
This operation is permanent and cannot be undone.

API Request Limits

These API limits determine how many API calls you can make within a given time period. There are two types of request limits: hourly and minutely.
For more information on the API limits for your account, you can call the API Limits endpoint.

Types of Limits

  • Hourly Limit - The number of requests allowed within one hour.
  • Minutely Limit - The number of requests allowed within one minute.

Default Limits

  • The default hourly limit is set to 600 requests.
  • The default minutely limit is set to 30 requests.

Response Headers Related to Limits

The following response headers also include information about the API limits:

  • X-RateLimit-PerHour-Limit - Indicates the maximum number of requests allowed per hour.

  • X-RateLimit-PerHour-Remaining - Shows the number of requests remaining in the current hour.

  • X-RateLimit-PerMinute-Limit - Denotes the maximum number of requests allowed per minute.

  • X-RateLimit-PerMinute-Remaining - Indicates the number of requests remaining in the current minute.

If you exceed these limits, you may receive an error response indicating that the rate limit has been reached.

The possible errors that can be returned are shown in the table below:

Response Headers

The following response headers are included in the API response for every successful request:

  • X-RateLimit-PerHour-Limit - Indicates the maximum number of requests allowed per hour.

  • X-RateLimit-PerHour-Remaining - Shows the number of requests remaining in the current hour.

  • X-RateLimit-PerMinute-Limit - Denotes the maximum number of requests allowed per minute.

  • X-RateLimit-PerMinute-Remaining - Indicates the number of requests remaining in the current minute.

  • X-Kanbanize-Version - Shows the current version of Businessmap.

Filtering and Expanding Resources

By using both expand and filters, you can refine your queries and retrieve more detailed and relevant data.
Filters allow you to narrow down results based on specific criteria, ensuring that only the most relevant information is returned.
Expand is used to get more details about a specific object that is returned for an endpoint without having to call a separate endpoint.

Info

Please note that filtering and expanding are not available for all endpoints. If they are available, they will be specified as query parameters for the selected endpoint.

Filtering

Filters are applied to refine the data returned by the API, allowing you to focus on specific attributes or values that match your requirements.
Common filters include:

  • from - Filters results that occurred after a specific date and time in YYYY-MM-DD HH:mm:ss format.
  • to - Filters results that occurred before a specific date and time in YYYY-MM-DD HH:mm:ss format.
  • from_date - Filters results that occurred after a specific date in YYYY-MM-DD format.
  • to_date - Filters results that occurred before a specific date in YYYY-MM-DD format.

Expanding

When expanding is enabled, you can request additional details about specific properties in the response.
To do so, simply list the properties available for the selected endpoint you wish to expand as query parameters, e.g. expand=custom_fields.

Pagination

Pagination is used to split large sets of results into smaller, more manageable pages.
It allows users to retrieve a subset of results at a time, improving performance and providing a more user-friendly experience when dealing with extensive data sets.
If pagination is available results are always returned in pages.

Info

Please note that pagination is not available for all endpoints. If it is available, the specific endpoint will list the available query parameters.
Additionally in the response body, a distinct pagination object will appear at the top, containing the relevant pagination details.

Pagination Query Parameters

You can control the pagination behavior using the following query parameters:

  • page - This parameter specifies which page of results to return. By default, the API returns the first page.

  • per_page - This controls the number of results per page. The default value is 100, and the maximum allowed is 200.

By using these parameters, you can navigate through large datasets more effectively.
