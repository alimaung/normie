# Verzeichnis Automation Scripts

## Overview

This directory contains scripts for automating the processing of NEW ATS (Antrag für Teile und Stoffe) applications. The scripts extract data from PDF forms, generate sequential IDs, and write tracking information to Excel sheets.

## Key Scripts

### `main_workflow.py`
**Purpose**: Main orchestrator for NEW application processing

**Functionality**:
- Coordinates the complete workflow for processing NEW ATS applications
- Integrates PDF processing, ID generation, and Excel writing
- Validates input files and handles errors
- Provides command-line interface

**Workflow Steps**:
1. Process PDF and extract form data (`pdf_processor.py`)
2. Generate new IDs (`id_generator.py`)
3. Write to Excel sheets (`excel_writer.py`)

**Usage**:
```bash
python main_workflow.py path/to/pdf_file.pdf
```

**Current Limitation**: Only processes "Neubedarf" (new requirements), rejects "Bedarfsänderung" (change requests)

---

### `id_generator.py`
**Purpose**: Generate sequential TKZ and Antragsnummer IDs

**Functionality**:
- Reads `TKZ.xls` to find the last TKZ number (8-digit format: `01044397`)
- Reads `Verzeichnis.xlsb` to find the last Antragsnummer for current year (format: `158/2025`)
- Increments and returns new IDs
- Uses COM interface to preserve Excel text formatting (leading zeros)

**Key Functions**:
- `get_last_tkz_number()`: Finds highest TKZ number in TKZ.xls
- `get_last_antragsnummer()`: Finds highest Antragsnummer for current year
- `generate_new_ids()`: Returns tuple of (new_tkz_str, new_antragsnummer_str)

**ID Formats**:
- **TKZ**: `01044398` (8-digit with leading zeros)
- **Antragsnummer**: `159/2025` (XXX/YYYY format)

**Performance**: Searches from bottom-up for efficiency (avoids reading 5000+ rows)

---

### `excel_writer.py`
**Purpose**: Write extracted PDF data to Excel tracking sheets

**Functionality**:
- Maps PDF form fields to Excel column positions
- Creates new rows in both TKZ.xls and Verzeichnis.xlsb
- Detects location (OU/DW) from PDF text fields
- Uses COM interface for native Excel file handling

**Column Mappings**:

**TKZ Sheet**:
- Column A: TKZ (autogenerated)
- Column B: TO-Nummer (always "N/A")
- Column D: Benennung (Field 3)
- Column E: Projekt (always "Allgemein")
- Column F: Antragsteller Name (Field 2a)
- Column G: Abteilung (Field 2c)
- Column H: Datum (Field 2b)

**Verzeichnis Sheet**:
- Column A: Antragsnummer (autogenerated)
- Column B: TKZ (from TKZ sheet)
- Column C: Freigabe status ("TBD")
- Column D: Erzeugnisrelevanz (Field 13)
- Column F: Benennung (Field 3)
- Column G: Produktzulassung (Field 18e)
- Column H: Antragserstellungsdatum (Field 2b)
- Column J: Antragsteller Abteilung (Field 2c)
- Column K: Einsatzort / Standort (detected OU/DW)
- Column L: Antragsteller Name (Field 2a)
- Column V: Current date
- Column W: "Normstelle"
- Column X: SAP status (based on Field 15b)

**Key Functions**:
- `create_tkz_row()`: Builds row data for TKZ sheet
- `create_verzeichnis_row()`: Builds row data for Verzeichnis sheet
- `detect_location_from_pdf()`: Extracts OU/DW from PDF text
- `append_to_excel_file()`: Writes row to Excel using COM
- `write_to_excel_sheets()`: Orchestrates writing to both sheets

---

### `pdf_processor.py`
**Purpose**: Extract and validate PDF form data

**Functionality**:
- Extracts form fields from ATS PDF forms
- Validates that the application is "Neubedarf" (new requirement)
- Processes different field types (text, buttons, signatures)
- Returns structured data ready for Excel processing

**Key Functions**:
- `extract_pdf_fields_memory()`: Extracts all form fields from PDF
- `extract_field_value()`: Converts PDF field data to human-readable values
- `validate_neubedarf()`: Ensures this is a new requirement (not a change)
- `process_pdf_for_excel()`: Main function that returns processed data

**Field Processing**:
- **Text fields**: Extracts text value, cleans whitespace
- **Button fields**: Maps button states to labels (e.g., "/0" → "Neubedarf")
- **Signature fields**: Returns "SIGNED" or "NOT_SIGNED"

**Current Limitation**: Rejects "Bedarfsänderung" applications

---

### `pdf_fields.py`
**Purpose**: Low-level PDF form field extraction

**Functionality**:
- Uses PyPDF2 to extract form fields from PDF
- Handles signature fields (converts binary to base64 for JSON)
- Natural sorting of field names (handles numeric sorting correctly)
- Can save to JSON or return in-memory dictionary

**Key Functions**:
- `extract_form_fields()`: Main extraction function
- `clean_signature_field()`: Processes signature data for serialization
- `natural_sort_key()`: Sorts field names naturally (e.g., "2", "10", "20" not "10", "2", "20")

**Output**: OrderedDict of field names → field data

## Workflow Integration

### Current State: NEW Application Processing Only

This automation currently handles **Stage 3: Workflow Router → NEW Workflow Pipeline**:

```
Email Received
    ↓
[Stage 1: ATS Detector] → HIGH/MEDIUM
    ↓
[Stage 2: Stage Detector] → TYPE = NEW
    ↓
[Stage 3: Workflow Router] → new_workflow
    ↓
[Verzeichnis Automation]
    1. Extract PDF data (pdf_processor.py)
    2. Generate IDs (id_generator.py)
    3. Write to Excel (excel_writer.py)
    4. Update PDF with IDs (TODO)
    5. File operations (TODO)
    6. Email out (TODO)
```

### What's Implemented ✅
- PDF form field extraction
- ID generation (TKZ + Antragsnummer)
- Excel writing (TKZ + Verzeichnis sheets)
- NEW application validation

### What's Missing ❌
- Email integration (currently processes PDFs directly)
- PDF updating (filling Field 1 and Field 51 with generated IDs)
- File operations (renaming, organizing attachments)
- Email composition and sending
- ONGOING workflow support
- CHANGE workflow support

---

## Required Modifications for Full Workflow Support

### 1. **ONGOING Workflow Support**

**Current Issue**: Scripts only handle NEW applications with empty Field 1 and Field 51.

**Required Changes**:

**`pdf_processor.py`**:
- Remove `validate_neubedarf()` restriction
- Add function to detect workflow stage from filled fields:
  - Fields 2-24 filled → Stage 2 (ChemScan)
  - Fields 2-31 filled → Stage 3 (UWS)
  - Fields 2-38 filled → Stage 4 (HSE)
  - Fields 2-49 filled → Stage 5 (LAB)
  - Fields 2-50 filled → Stage 6 (Final)
- Extract ATS number and TKZ from existing form (Field 1, Field 51)
- Extract updated signatures and evaluations

**`id_generator.py`**:
- Add function to read existing IDs from PDF (don't generate new ones)
- `get_existing_ids_from_pdf()`: Extract Field 1 and Field 51 values

**`excel_writer.py`**:
- Add function to update existing rows instead of creating new ones
- `update_excel_row()`: Find row by ATS number, update specific columns
- Map department signatures to appropriate columns
- Update status fields based on stage

**`main_workflow.py`**:
- Add workflow type detection (NEW vs ONGOING)
- Route to different processing paths:
  - NEW → Generate IDs, create new rows
  - ONGOING → Read existing IDs, update existing rows

---

### 2. **CHANGE Workflow Support**

**Current Issue**: Scripts reject "Bedarfsänderung" applications.

**Required Changes**:

**`pdf_processor.py`**:
- Remove rejection of "Bedarfsänderung"
- Add validation for CHANGE requests:
  - Field 5 = "Bedarfsänderung"
  - Field 20 must reference previous ATS number
  - Field 1 and Field 51 should already exist
- Extract change reason from Field 19

**`id_generator.py`**:
- For CHANGE: Read existing IDs from PDF (Field 1, Field 51)
- Do NOT generate new IDs

**`excel_writer.py`**:
- Add CHANGE-specific logic:
  - Find existing row by ATS number
  - Update specific fields based on change type
  - Preserve historical data
  - Add change tracking columns

**`main_workflow.py`**:
- Add CHANGE workflow path:
  - Extract existing IDs
  - Identify change type (manufacturer, location, packaging, etc.)
  - Update appropriate Excel fields
  - Flag for special handling

---

### 3. **Email Integration**

**Current Issue**: Scripts process PDFs directly, not integrated with email workflow.

**Required Changes**:

**New Module: `email_integration.py`**:
- Extract attachments from `.msg` files
- Identify ATS form PDF from attachments
- Pass PDF path to `main_workflow.py`
- Handle multiple attachments (SDS, TDS, COC)

**`main_workflow.py`**:
- Accept email metadata (subject, sender, attachments)
- Extract PDF from email attachments
- Pass context to processing functions

---

### 4. **PDF Updating**

**Current Issue**: Generated IDs are written to Excel but not back to PDF.

**Required Changes**:

**New Module: `pdf_updater.py`**:
- Fill Field 1 (Request No.) with generated Antragsnummer
- Fill Field 51 (TKZ) with generated TKZ
- Preserve existing signatures and form structure
- Save updated PDF

**`main_workflow.py`**:
- After Excel writing, update PDF with IDs
- Save updated PDF to staging area

---

### 5. **File Operations**

**Current Issue**: No file renaming or organization.

**Required Changes**:

**New Module: `file_operations.py`**:
- Rename ATS form: `XXX/YYYY_XXXXXXXX.pdf`
- Rename SDS: `XXX/YYYY_XXXXXXXX_SDS.pdf`
- Rename TDS: `XXX/YYYY_XXXXXXXX_TDS.pdf`
- Copy files to appropriate directories:
  - ATS: `Antrag/YYYY/`
  - SDS: `Sicherheitsdatenblatt/`
  - TDS: `Datenblatt/`

**`main_workflow.py`**:
- After PDF updating, perform file operations
- Update Excel hyperlinks to point to new file locations

---

### 6. **Workflow Stage Detection**

**Current Issue**: No detection of which workflow stage an ONGOING application is at.

**Required Changes**:

**New Module: `stage_detector.py`**:
- Analyze filled form fields to determine stage
- Check sender email for department identification
- Check subject line for ATS number patterns
- Return stage classification (2, 3, 4, 5, 6)

**`main_workflow.py`**:
- Use stage detector for ONGOING applications
- Route to stage-specific processing logic
