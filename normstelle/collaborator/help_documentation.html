🏠 System Overview

🎯 System Purpose

This system enables multiple users to safely edit the same Excel workbook simultaneously without conflicts or data loss.

By using separate user files and a controlled merge process, teams can collaborate efficiently on large datasets while maintaining data integrity and audit trails.

✅ Key Benefits

  • Concurrent Editing: Multiple users can work simultaneously
  • Conflict Resolution: Automatic detection and manual resolution of overlapping edits
  • Data Integrity: No data loss or corruption from simultaneous access
  • Audit Trail: Complete tracking of who changed what and when
  • Controlled Merging: Supervised integration of all changes
  • Rollback Capability: Ability to undo problematic changes

The Collaborative Process

  1. Distribution: Users copy rows from main workbook to their personal .xlsm files
  2. Independent Editing: Users edit their copies without interfering with others
  3. Ready Marking: Users mark completed edits with column AB = 1
  4. Collection: System gathers all ready changes into staging area
  5. Conflict Detection: Automatic identification of overlapping edits
  6. Manual Resolution: Human review and decision-making for conflicts
  7. Controlled Merge: Approved changes are integrated into main workbook
  8. Synchronization: User workbooks are updated to reflect merged state

Daily Workflow

🌅 Morning Setup

Start of collaborative session:

  • First user opens main workbook (Verzeichnis.xlsb)
  • Other users work with their personal .xlsm files
  • Users copy relevant rows from main sheet to their files
  • Collaborative editing begins independently

📝 During the Day

Ongoing collaborative work:

  • Users edit their personal copies independently
  • No interference or locking between users
  • Users mark completed work with AB = 1 when ready
  • Periodic collection and review of ready changes

🔄 Merge Process

Integration of changes:

  • Administrator runs "Fetch User Edits" from Control panel
  • System collects all ready changes into Staging area
  • Conflicts are automatically detected and flagged
  • Manual resolution of any conflicts in Conflicts sheet
  • "Merge Changes" applies approved edits to main workbook

🚀 Getting Started

For New Users

  1. Receive your personal workbook (e.g., Verzeichnis_YourName.xlsm)
  2. Copy rows you need to edit from the main "Teile und Stoffe" sheet
  3. Make your changes in your personal file
  4. Mark rows as ready by setting column AB = 1
  5. Coordinate with administrator for merge timing

For Administrators

  1. Open the main workbook (Verzeichnis.xlsb)
  2. Navigate to Control sheet for main dashboard
  3. Use "Fetch User Edits" to collect ready changes
  4. Review Staging area for overview of all changes
  5. Resolve conflicts in Conflicts sheet if needed
  6. Run "Merge Changes" to apply approved edits

📋 Staging Area Overview

🎯 Purpose of the Staging Area

The staging area is your central hub for reviewing all user changes before they're merged into the main workbook.

It collects all user edits marked as 'ready' (AB=1) from user workbooks and prepares them for review, conflict detection, and eventual merging.

✅ What Happens Here

  • Collection: All ready user changes are gathered in one place
  • Analysis: Changes are compared against the main sheet
  • Conflict Detection: Overlapping edits are automatically identified
  • Change Highlighting: Modified cells are visually marked
  • Metadata Tracking: User names, timestamps, and unique IDs are recorded

Understanding Conflicts

⚠️ Conflict Detection Logic

Conflicts occur when multiple users edit the same Antrag-nummer (Column E in the data).

The system automatically detects these by comparing the Antrag-nummer values across all staged changes.

How to Identify Conflicts

  • Column A = 0: This row has conflicts with other users' edits
  • Same Antrag-nummer: Multiple rows with the same identifier in column E
  • Different users: Column C shows different user names for the same record
  • Red highlighting: Shows which specific cells were changed

Staging Workflow

Step 1: Data Collection

Triggered by "Fetch User Edits" from Control panel:

  • System scans all user .xlsm files
  • Finds rows where column AB = 1 (marked as ready)
  • Copies these rows to the staging area
  • Adds metadata (ID, user, timestamp)

Step 2: Change Analysis

System automatically:

  • Compares each staged row with the main sheet
  • Highlights changed cells in red
  • Detects conflicts by matching Antrag-nummers
  • Sets conflict flags in column A

Step 3: Review Process

Your review tasks:

  • Scan through all staged changes
  • Verify that changes look reasonable
  • Identify any obvious data quality issues
  • Note which records have conflicts (A=0)

🔄 Next Steps

After reviewing the staging area:

  1. No conflicts (all A=1): Return to Control panel and merge changes
  2. Conflicts present (some A=0): Go to Conflicts sheet to resolve
  3. Data quality issues: Contact users to clarify or correct
  4. Ready to merge: Use Control panel "Merge Changes" function

⚔️ Conflicts Resolution System

⚠️ Critical Information

Conflicts occur when multiple users edit the same record (same Antrag-nummer). You must resolve these manually to ensure data integrity and prevent data loss.

The system cannot automatically decide which version is correct - this requires human judgment based on business rules and data quality.

Understanding the Conflicts Interface

What You See on the Conflicts Sheet

  • ORIGINAL rows: Show the current data from the main "Teile und Stoffe" sheet
  • User modification rows: Show proposed changes with user name and timestamp
  • Red highlighting: Indicates which specific cells were actually changed
  • Thick borders: Group related conflicts together visually
  • Color coding: Green = selected, Light red = rejected, Original colors = unchanged
Example Layout:
┌─────────────────────────────────────────────────────────┐
│ ORIGINAL │ Select │ Data columns... │
│ User1-ID123 │ 1 │ Modified data + unchanged data │
│ User2-ID124 │ 0 │ Different changes + unchanged │
└─────────────────────────────────────────────────────────┘

Step-by-Step Resolution Process

Step 1: Analyze the Conflict

Compare the ORIGINAL data with each user's proposed changes:

  • Look at the red highlighted cells - these show exactly what was modified
  • Check the user names and timestamps to understand who made what changes when
  • Consider the business context - which changes make more sense?
  • Look for complementary changes that don't actually conflict

Step 2: Make Your Selection

In the 'Select' column (D), choose which version to keep:

  • 1 = ACCEPT this user's changes (will be merged)
  • 0 = REJECT this user's changes (will be ignored)
  • Empty/Blank = No decision made yet (prevents merging)

Important: Only ONE version per conflict group can be selected as "1"

Step 3: Verify Your Decision

After making selections:

  • Review the visual feedback (green = selected, light red = rejected)
  • Double-check that your selection makes business sense
  • Ensure all conflicts in the group have been decided
  • You can change your mind - just select a different option

Visual Feedback System

🎨 Color Coding Guide

  • Green background: Selected for merge (value = 1)
  • Light red background: Rejected (value = 0)
  • Red highlighted cells: Changed data (shows what was modified)
  • Original background colors: Unchanged data (preserved from original formatting)
  • Thick borders: Group boundaries around related conflicts

💡 Pro Tips & Best Practices

Efficient Conflict Resolution

  • Binary Selection: Only ONE version per conflict can be selected
  • Automatic Rejection: Selecting one automatically rejects others in the same group
  • Change Your Mind: You can always select a different option
  • Clear Selection: Delete the value in column D to reset
  • Use Ctrl+Z: Undo accidental selections
  • Focus on Changes: Pay attention to red highlighted cells
  • Consider Timestamps: More recent changes might be more relevant
  • Business Logic: Apply your domain knowledge to make decisions

⚠️ Common Mistakes to Avoid

  • Don't leave conflicts unresolved - empty selections prevent merging
  • Don't select multiple versions - only one can be "1" per group
  • Don't ignore timestamps - they provide important context
  • Don't rush decisions - take time to understand the changes
  • Don't forget to save - your selections need to be preserved

✅ After Resolution

Once you've resolved all conflicts:

  1. Return to the Control sheet
  2. Click "Merge Changes" to apply your decisions
  3. The selected changes will be applied to the main sheet
  4. User workbooks will be updated to reflect the merge
  5. The staging and conflicts areas will be cleared
